# Passes and pipelines

Generated by `scripts/gen_passes_doc.py` from the TableGen definitions of the passes and the registry of `ops/lib/Pipelines/Pipelines.cpp`.
Every pass is available in `ops-opt` under its name (`ops-opt file.mlir -<pass>`); the pipelines are also named pipelines of `ops-opt`

## Transforms passes

### `ops-materialize-kernels`

*clone the body of each ops.kernel into the ops.par_loops that call it.*

Runs on `ModuleOp`.

A `par_loop` with a `kernel` symbol and an empty body is the unmaterialised form the lifter produces. This pass fills in its body from the `ops.kernel` of that name: - the i-th accessor parameter of the kernel is the i-th dat operand's block argument, the i-th reduction parameter the i-th reduction's; - a global parameter `!ops.gbl<T, n>` takes the next n scalar operands: `ops.gbl_read %g[c]` becomes the scalar block argument of component c; - `ops.const_ref` without an index becomes a new scalar argument of the chain (one per constant, offset and type), passed to every loop that uses it; the arguments are recorded in the chain attribute `ops.binding_consts`, an array of `{name, offset, arg}` the lifter reads back to bind them. A `const_ref` with a dynamic index stays and is handled by `ops-specialize-consts`. The result is verified: a read or write at an offset outside the operand's stencil is an error.

### `ops-specialize-consts`

*fold constants whose values are known, and unroll the loops that index them.*

Runs on `ModuleOp`.

The values of constants come from the chain attribute `ops.const_values`, a dictionary from the name of a constant to its bytes (`array<i8: ...>`, little endian, as `ops_decl_const` registered it). Which constants to fold: the option `names`, by default every constant whose entry in the chain attribute `ops.const_roles` is `"bound"`. - arguments recorded in `ops.binding_consts` for such a constant are replaced by their value in every loop and removed from the chain signature; - `scf.for` loops with a constant trip count of at most `max-trip-count` that index such a constant with a dynamic `ops.const_ref` are fully unrolled; - `ops.const_ref` of such a constant with a constant (or no) index is replaced by its value; - canonicalisation then folds what became constant. A `ops.const_ref` with a dynamic index that remains is an error: a chain with such a reference cannot be compiled and the executor declines it.

Options: `max-trip-count` (int64_t, default 256): largest constant trip count of a loop that is fully unrolled

### `ops-fuse-point-local`

*merge the loops of a chain that can run point by point in one kernel.*

Runs on `ModuleOp`.

Plans the chain with the dependence analysis (`ops.range_values` gives the concrete ranges) and rewrites it along the plan: a group of loops becomes one `ops.par_loop` whose dat operands are the union of the members' (deduplicated by value, access modes joined, stencil points united) and whose body is the members' bodies, in order. Independent loops move next to the loops they fuse with. Loops with a reduction are never fused and nothing moves across them. The kernels of all loops must be materialised (`ops-materialize-kernels`). `ops.range_values` is rewritten for the new loops; the fused loops carry `ops.fused_loops`, the `loop_id`s of their members.

Options: `max-loops` (int64_t, default 8): upper bound on the loops of a group; `reorder` (bool, default true): let independent loops move past each other; `placement` (std::string, default "earliest"): which legal group a loop joins: earliest or latest; `guarded` (bool, default false): fuse loops of different ranges over their bounding box (not implemented yet); `box-ratio` (double, default 1.0): largest bounding box volume relative to the members' volumes (guarded fusion)

### `ops-forward-stores`

*use the value stored to a dat point instead of reading it back; narrow access modes.*

Runs on `ModuleOp`.

Inside a loop body, `ops.write %a[o] {comp = c}, %v` followed by `ops.read %a[o] {comp = c}` of the same accessor, with no write to that accessor in between, uses `%v`. The pass then narrows the access modes of the loop: an operand that is no longer read becomes `write` (it need not be loaded), one that is never written `read`.

### `ops-outline-groups`

*make each loop of a chain its own ops.chain, called from the original.*

Runs on `ModuleOp`.

Each `ops.par_loop` of a chain becomes `ops.chain @group_<n>` with only the operands of the loop, and the original chain becomes a list of `ops.call`s in execution order. Constants the loop body captured from the chain are copied into the group. The planner and the executor compile and launch the groups.

### `ops-specialize`

*replace what is known at JIT time by constants.*

Runs on `ModuleOp`.

`mode=ranges`: the range operands of every loop become the constants of the chain attribute `ops.range_values` (compile-time trip counts, so the code generator can unroll and vectorise without remainder checks). The chain keeps its arguments, the ABI does not change. The compiled code is only valid for these ranges: the cache key must contain them. `mode=shapes` does that and also uses the extents of the dats (the chain attribute `ops.shape_values`, per argument the sizes in OPS order): `convert-ops-to-scf` gives the memrefs static shapes and strides, which makes the address arithmetic constant. `mode=none` does nothing.

Options: `mode` (std::string, default "none"): none, ranges or shapes

## Conversion passes

### `convert-ops-to-scf`

*lower a group (an ops.chain of one ops.par_loop) to a func.func with scf.parallel.*

Runs on `ModuleOp`.

The compiled group ABI (plan section 4.6). The function takes, in this order: 1. one memref per distinct dat of the loop, in order of first appearance; 2. the shifts: one `index` per dat and dimension (dat-major, dimension-minor, OPS axis order); 3. the range: lo, hi per dimension (OPS axis order, x first); 4. the displacement of the block, one `index` per dimension (`ops.index d` is `i_d + disp_d`); 5. the scalars of the loop (distinct chain arguments, in order of first appearance). It returns the values of the reductions (neutral element combined over the range). With `target=gpu` the function is the host side of a kernel launch instead: the arguments after the scalars are one rank-0 memref per reduction (device memory the caller initialised with the neutral element, and reads back afterwards), each thread combines its partial value into it with an atomic, and nothing is returned. The threads are a block of `block` threads per dimension (x fastest); a thread outside the range does nothing. A dat of an OPS block of rank r with c components is a `memref<?x..xT>` of the r dimensions in memory order (z, y, x: OPS dimension d is memref dimension r-1-d) with a trailing dimension of size c if c > 1. Array of structures (default): the strides are [?, .., c, 1] (or [?, .., 1] for c = 1); structure of arrays (`soa`): [?, .., 1, ?]. An access at offset o of a dat with stencil stride s along d reads the memref index `i_d * s + o_d + shift_d`. The function is named like the chain, or as the chain attribute `ops.func_name` says; a private declaration of that name in the module (for a caller) is replaced by the definition. With `loops=affine` (CPU only) the loops are `affine.parallel` (the outer dimensions) and `affine.for` (x), and the accesses at constant stencil offsets are `affine.load` / `affine.store` of `shift + i + offset` (the shifts and the range are function arguments, so symbols), which lets affine-level transformations (tiling, interchange, unroll-and-jam, ...) work on the group before `lower-affine`. Data-dependent accesses (`ops.read_dyn`) stay `memref.load`. A loop with reductions keeps the `scf` form (the function then has `ops.loops = "scf"`); the attribute `ops.loops` is set whenever `loops=affine` is asked for. The function is marked `llvm.emit_c_interface`, its memref arguments `llvm.noalias`, and carries the attribute `ops.abi` describing the argument groups. Chains that contain `ops.call`s, and chains without a loop, are left alone. A group called from another chain in the same module cannot be converted (its signature changes): split the groups into modules of their own first.

Options: `soa` (bool, default false): structure-of-arrays layout of multi-component dats; `target` (std::string, default "cpu"): cpu: scf.parallel over the outer dimensions with a sequential x loop; gpu: a gpu.launch with one thread per point; `loops` (std::string, default "scf"): cpu: scf (scf.parallel / scf.for, memref accesses) or affine (affine.parallel / affine.for, affine accesses; loops without reductions)

### `ops-hoist-accumulators`

*move the reduction accumulators of a lowered group out of the loop body.*

Runs on `ModuleOp`.

`convert-ops-to-scf` accumulates a loop's reductions in a scalar `memref.alloca` (marked `ops.accumulator`) that each iteration of the parallel loop initialises with the neutral element. An alloca in a loop body is a dynamic allocation after lowering: it makes LLVM bracket the body with stack save/restore and keeps it from promoting the accumulator to a register (so no vectorised reduction). This pass moves each marked alloca to the entry of the nearest enclosing `omp.parallel` region (one per thread) or, without OpenMP, of the function. Run it after `convert-scf-to-openmp`.

### `ops-mark-noalias`

*mark the data pointers of the dat arguments of a lowered group noalias.*

Runs on `ModuleOp`.

Run after the conversion of the group function to the LLVM dialect: the memref arguments of `func.func` are expanded to a descriptor (allocated pointer, aligned pointer, offset, sizes, strides) and the attribute `llvm.noalias` of the argument does not reach the pointers the code loads and stores through. This pass sets it on the aligned pointer of each dat, using `ops.abi.noalias_args` that `convert-ops-to-scf` recorded. Distinct dats of a group never overlap (the lifter deduplicates by dat), which lets LLVM vectorise without run-time overlap checks.

### `ops-fp-contract`

*allow floating point operations to be contracted into fused multiply-adds.*

Runs on `ModuleOp`.

Sets the `contract` fast-math flag on every floating point `arith` operation, so that the code generator may fuse a multiplication and an addition (what nvcc and clang do by default within an expression). The results then differ from unfused code in the last bits. Run after `convert-ops-to-scf`.

### `ops-gpu-kernel-attrs`

*mark the dat pointers of the kernels of a gpu.module noalias.*

Runs on `gpu::GPUModuleOp`.

Run after `convert-gpu-to-nvvm`: a memref argument of a kernel is expanded to a descriptor (allocated pointer, aligned pointer, offset, sizes, strides) and the pointers a kernel loads and stores through are the aligned ones. The dats of a group never overlap (the lifter deduplicates by dat), which is the `__restrict__` of the stock CUDA code: with it the code generator may move loads past stores and share loads of the same address.
